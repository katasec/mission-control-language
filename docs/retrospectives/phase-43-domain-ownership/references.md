# Reference evidence and decisions

Read-only source inspection, 2026-09-06. These are pinned snapshots, not claims about later versions. No reference repository was modified and its test suite was not executed. Source/test inspection supports the stated behavior; it is not live verification of those products. Use DeepSeek's ownership method first when concepts are conflated, then test it against MCL's actual consumers, Native AOT and distributed guarantees.

## Evidence-backed conclusion

The sources support named ownership, narrow consumers, explicit completion and lifecycle boundaries. They do not establish that MCL needs more runtime processes, dynamic plugins, a new generic coordinator, a new datastore or one .NET project per service. The approved refactor remains constrained to [MCL's end state](end-state.md) and existing supported behavior.
