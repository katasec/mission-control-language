# Phase 43.22 — audited source boundary

All 88 changed files are classified: 33 C#/Razor sources, five stylesheets, six asset/build changes, twelve tests, and thirty-two documentation/reference files. Renames count once.

Application source disposition: ten retain, seventeen revise, five reconstruct named responsibilities, one delete.

Retain means no semantic reconstruction is justified by present evidence, not blanket release approval. Revise preserves the principal implementation with the specified edits. Reconstruct responsibility identifies exactly what is replaced and what remains; it does not mean deleting every line in the file. Delete removes the obsolete implementation.

## Plan application — authoritative changes to the audit disposition

This is the complete **audited increment**, not a command to copy all these files into current
main. The [reconstruction hub](phase-43.22-project-mission-reconstruction.md) and its task contracts
are authoritative for implementation. Two design decisions refine the audit boundary:

- Delete the old MissionRunThread implementation and replace its responsibility with Host summaries
  and Runtime read state. Replace ProjectMissionRuntimeSession with the two task-3 owners.
- Keep current main's Core/CLI/lock format. Do not port the earlier Task 3 OCI prerequisite bundle,
  regenerate unrelated mission locks, or copy the old plan/rules files. The local Explorer slice
  is defined in task 4. Mission assets are ported/regenerated using the existing main format.

Files here described as retained may need small contract wiring changes; retention is not a
release approval. New owners and bounded query adapters are explicitly named in tasks 1–4.
The 23 old SVGs are audited reference files: this plan carries only the selected references it
actually binds. Do not copy all of them by default.
