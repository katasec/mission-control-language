## Package-family consequences

Pinned source UI6f4e0cde3890d8ce2510ac0451b861863e4aeeaa / Terminal5517cb3d8cdf0532ecc89260067064f98cde6137. Current public UI/Markdown/TextMate3.10.0 and Terminal2.2.0 remain unchanged by this investigation.

Even a methods-only UI change requires a coherently built/packed/tested UI + Markdown + TextMate family and its generator packaging. Reusing unchanged source generator code does not remove that release/build dependency. A fork cannot leave official and fork UI assemblies simultaneously resolved under identical namespaces/types. Package IDs/versions/distribution/ownership/namespace identity require an operator Type1 decision; no numeric release or IDs are invented here.

## Additional bounded native rendering observation

At width20 the actual code Paragraph echo echo\n  echo 👩‍💻\n displays the ZWJ emoji. At width8 its native bounds are(0,7)8x4, rendered code rows omit the emoji in both themes, yet a genuine full native drag copies exactly echo echo\n  echo 👩‍💻\n with one write. This is observed payload/render divergence, not a diagnosed general library bug or permission to fix it. The source has distinct wrapping slice/start and grapheme mechanisms; root must determine whether this case needs a separate native correction or another explanation before assuming exposure of private APIs alone closes all geometry. The facade40–80line estimate excludes any such correction. No mapping adapter, alternative wrap engine or native patch was built.
